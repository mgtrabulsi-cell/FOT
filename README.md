# GameWire

A responsive NFL hub with live scoreboards, weekly matchups, player statistics, and a favorite-centered feed called Your Locker Room.

Site interface copy uses provider-neutral data labels (including "Loading data...") rather than naming the feed provider. Feed URLs, source links, caching, and refresh behavior are unchanged.

Scores refresh immediately when returning to a visible app/tab, restoring a page, or reconnecting; open game box scores and Locker Room plays also refresh on return rather than waiting for their polling timers. Web and native score/box-score requests explicitly asking for fresh data wait for the network read instead of returning a saved-first response. Saved data remains available on connection failures. Regular scoreboard polling remains every 30 seconds, with live box scores and favorite plays every 15 seconds. Closed or OS-suspended apps cannot guarantee background polling.

NBA pregame comparisons, team season statistics, rosters, Stat Hub directories/scoring order, league browsing, and opened player profiles/game logs also save locally. Saved views render immediately while ESPN refreshes in the background and remain visible offline or after a failed refresh. The selected date's matchup rosters and team averages warm automatically without opening each game; successful team preloads and scoring averages are reused for five minutes to avoid repeated request bursts. First-time uncached data still requires ESPN, and missing pregame box-score values are never invented.

## Run locally

Install Node.js 20 or newer, then run:

```sh
npm install
npm run dev
```

Open the local URL printed by Vite. `npm run build` creates a production build.

The VS Code task **Start GameWire dev server** is also configured for launching the app.

Desktop views use an 85% interface scale, with a compact matchup scoreboard and larger player names and headshots in The Wire, Stat Hub's player directory, and player cards. Stat Hub retains its extra player-area emphasis. Screens 760px wide or narrower keep the unscaled mobile layout.

Desktop account profiles have an additional 130% scale, larger text and form controls for readability, and single-column settings on narrower desktop screens. Mobile profile sizing is unchanged.

Locker Room uses an additional 120% desktop scale for easier reading, slightly less than the profile screen. Mobile Locker Room sizing is unchanged.

The original navy-blue theme uses bold crimson (`#cc2633`) for selection indicators, live accents, and Stat Hub chart bars. Filled red controls use a deeper crimson with white labels for readability; official team colors remain unchanged.

Player cards use slimmer per-game chart bars. Wide receiver and tight end cards include Targets in the draggable stat wheel, using ESPN's game box-score values and retaining unavailable values rather than estimating them.

Stat Hub player cards stay open during background feed and saved-data refreshes, including while fresh game details are still loading. Switching to a different matchup closes the previous game's player card; Close, Escape, and backdrop dismissal remain available.

The Wire omits the large page title, description, and normal feed-status label on desktop and mobile, keeping a compact date/week row immediately below navigation so games and stats appear sooner. Feed warnings remain visible.

The Wire opens to a game board: every NFL game in the selected week is listed top to bottom in kickoff order. Each day (for example **Sunday, Oct 18**) has one heading, with its kickoff windows beneath it, from Thursday Night Football through the Sunday windows and Sunday Night Football to Monday Night Football. From 6:00 AM Monday until 2:00 AM Tuesday (Eastern), that Monday's MNF game moves to a highlighted **Tonight · Monday Night Football** panel at the top of the board, then returns to its normal place. Games at venues outside the United States (from ESPN's reported venue country) carry a green **INTL** tag with the host country's flag and an "International Series · City" label, on the board, in the game wheel, and in the matchup header. Each card shows status (live clock, final, or local kickoff time), both teams with records and scores, possession and field position for live games, and the venue. Selecting a game opens its stats area — pregame player season totals and Team Comparison before kickoff, or the live/final box score — with an **All games** button to return to the board and the game wheel for switching matchups. Game stats are only requested while a game is open. Selecting **The Wire** in navigation returns to the board; game notification links open their matchup directly.

On mobile, The Wire player box scores place each player's labeled stats on one compact horizontal row, with all stats visible without scrolling or wrapping into another row. Player identity stays above that row. The compact scoreboard uses stacked team rows with logos and names on the left and scores on the right. Stat Hub remains unchanged: its player-popup stat types retain a single horizontally scrollable, draggable row with touch-sized controls and a chart that fits the dialog width. The game selection wheels remain horizontally draggable.

The Wire's team/game search and Stat Hub's NFL player/team search expand inside the top banner, with white input text and separate queries for each view. On The Wire's game board, search narrows the list to matching games; inside an open game, search selects a matching game without removing the other games from the wheel and scrolls it into view. Clicking or touching anywhere outside the search, moving keyboard focus outside, Escape, or closing the search collapses it to the icon and clears the input text but preserves the selected game. Outside dismissal also works on controls that stop event propagation. Reopening starts with a blank field; typing a new search selects its match. Search has no red-dot indicator, and the clear action resets the search without removing any games.

Banner search uses a single rounded outline, without a nested input box or focus rectangle. Its clear X is borderless with a circular keyboard-focus indicator. Closing search removes the expanded panel from the page and dismisses input focus so no rounded border remains over the logo. LIVEWIRE posting-theme checkboxes use gray unchecked boxes and light-blue checked boxes with a dark checkmark; keyboard focus and native checkbox semantics are retained.

Mobile browsers and Median apps (760px wide or narrower) share the same website bottom bar for The Wire, Stat Hub, Analyst Desk, LIVEWIRE, and Locker Room, in that order, with identical icons, labels, colors, and spacing. Analyst Desk uses a desk icon and contains the Admins Picks and The Angle tabs; Stat Hub contains NFL Players and its player/team search. The logo, search, and account controls stay at the top; desktop browsers keep the tabs at the top. Navigation renders only inside the main app after sign-in or Continue as guest, never on splash, login, password recovery, or account-deleted screens. On mobile it is portaled directly to the document body and composited as a fixed bottom layer, independent of the scrolling header/content. The bar reserves content space and respects device safe areas. Keep Median's Bottom Tab Bar Default Mode **Hidden** in App Studio; the embedded bridge also disables native tabs at startup to prevent duplicates in older wrappers. Section links use `#wire`, `#stat-hub`, `#analyst-desk`, `#livewire`, and `#locker-room`; game/post notification links remain supported. Rebuild existing wrappers to apply the hidden startup default; on-device iOS/Android verification is still required.

On mobile, pull down at the top of the main app until **Release to refresh** appears, then release to reload the current section. The indicator appears only during the gesture or refresh; there is no refresh button or reserved space while idle. Short pulls, horizontal swipes, form controls, and nested scrollable panels do not trigger refresh. Offline attempts show a reconnect message without reloading. Refresh uses the normal saved-first startup and background revalidation; it does not clear saved data or force a splash on every data update.

The Wire and Stat Hub game wheels both show color-coded TNF, SNF, and MNF badges for primetime games, identified by kickoff time in Eastern Time.

Favorite NFL teams keep the order set in **Locker Room → Following → Teams**. Use the up/down controls to reorder them; the top team’s matchup is featured when it is live, or when no other NFL game is live. Once that matchup is final, the next later primetime game in the selected week is featured.

Before kickoff, Player Box Score hides category filters and offers **Total stats** (default) and **Avg stats** below the Player Box Score/Team Comparison tabs. Live and final games restore All, Offense, Defense, and Special Teams, with unrestricted individual game box scores. Player Box Score omits the team-total row beneath every player group in all game states; Team Comparison is unchanged.

Pregame Player Box Score can show season-to-date totals or per-game averages for the selected team. Avg stats divides every statistic, including touchdowns and fumbles, by the player's games played (`GP`); GP itself remains a count. Missing totals or invalid GP remain unavailable. Switching modes does not fetch data again. Live and final box scores remain game-specific.

Desktop pregame tables share fixed column widths across passing, rushing, and receiving, aligning player names, games played, yards, and touchdowns vertically. Unused stat slots stay blank rather than implying a value; mobile hides those slots and keeps the labeled stat grids.

The final column shows QB interceptions (`INT`), rushing fumbles in Rushing, and receiving fumbles in Receiving (`FUM`), not fumbles lost. Missing fumble data remains unavailable. Player portraits retain ESPN's full-resolution images with top-centered framing and larger desktop headshots.

Pregame QB passing stats omit sacks per game. Live and final box scores retain the sacks reported by ESPN.

Select a player's name in The Wire's pregame Player Box Score to open the same player card as Stat Hub, with position-specific draggable stat tabs, recent-game charts, and a favorite toggle. Closing the card keeps the current matchup and team selection.

## Deploy to GitHub Pages

The [deployment workflow](.github/workflows/deploy.yml) builds and publishes the site on pushes to `main`, or when run manually. It uses Node.js 22, installs from the lockfile with `npm ci`, and gets the asset base path from GitHub Pages automatically. Local development keeps relative asset paths; project Pages uses `/FOT/`, while a configured custom domain uses its Pages base path.

1. In the GitHub repository, open **Settings → Pages** and select **GitHub Actions** as the build and deployment source.
2. For accounts and synced favorites, add these **repository secrets** under **Settings → Secrets and variables → Actions**:
   - `VITE_SUPABASE_URL`: your Supabase project URL.
   - `VITE_SUPABASE_PUBLISHABLE_KEY`: your public publishable key. Alternatively, use `VITE_SUPABASE_ANON_KEY` for the legacy anon key.
   - `VITE_VAPID_PUBLIC_KEY`: optional public VAPID key, if you configured mobile push notifications.
3. Complete the Supabase schema setup described below. In **Supabase → Authentication → URL Configuration**, set the production Site URL to `https://mgtrabulsi-cell.github.io/FOT/` and add that exact URL to the allowed redirect URLs. Keep `http://localhost:5173/` allowed for local development. If using a custom domain, use its URL instead.
4. Commit and push your changes to `main`. In **Actions**, watch **Deploy to GitHub Pages**, or select **Run workflow** to redeploy the committed version.
5. Open `https://mgtrabulsi-cell.github.io/FOT/` after deployment succeeds. Test sign-in, email confirmation/password reset, and mobile notifications if enabled.

GitHub Actions does not read your local `.env.local`; configure the repository secrets before deploying, and rebuild after changing them. Without Supabase configuration, guest browsing is available but accounts and synced favorites are not. Notifications additionally require the Supabase functions and scheduled poller described below; GitHub Pages only hosts the frontend.

Choosing **Continue as guest** loads the live scoreboard and stats without signing in, including when Supabase accounts are configured.

**Analyst Desk and LIVEWIRE require a signed-in account in the app.** Guests can select either tab or open a direct story/post link, but see an account-required message and a **Sign in or create an account** button instead of content. Signing in preserves the selected destination. Guest sessions do not mount these sections, preload LIVEWIRE, or poll either section's unread status; previously saved posts are not displayed to guests. Existing signed-in sessions retain offline access to saved content and drafts. This navigation/rendering gate does not change public database/API policies.

LIVEWIRE preloads its public feed as soon as a signed-in member opens the main app and stays mounted while navigating between tabs, like The Angle. Opening the tab does not cancel an unfinished preload; loaded posts render immediately while subsequent refreshes run in the background. Previously saved posts also render synchronously after a restart. Theme filters show available matching posts immediately while fetching the full filtered result. Read/view tracking and periodic polling run only while LIVEWIRE is active, so preloading does not mark unseen posts as read or viewed. A first-ever visit still needs an initial download; refresh failures retain visible posts and show a retryable error.

All `VITE_` values are public in the built JavaScript, even when supplied through GitHub secrets. Never put a Supabase service-role/secret key, private VAPID key, or cron secret in them. Local environment files remain gitignored.

To verify the project-path build locally in PowerShell:

```powershell
$env:VITE_BASE_PATH = '/FOT/'
npm run build
npm run preview -- --host 127.0.0.1
Remove-Item Env:VITE_BASE_PATH
```

Open `http://127.0.0.1:4173/FOT/`. Assets, the web app manifest, and the notification service worker stay within the deployed path. This static deployment does not require a Node.js server.

### Fantasy Start/Sit graphic creator

Open **Analyst Desk → Fantasy → Start/Sit**. Admins and owners can create four-player **Must Start** or **Must Sit** graphics for QB, RB, WR, or TE using the approved 1080×1350 layout. Each slot searches ESPN active skill-player rosters and places the selected player's headshot/name above the opponent badge, with editable reasoning to the right. Opponents and home/away markers come from the selected week's loaded NFL games; missing schedules show **TBD**, never a guessed opponent or bye. Verify injuries and all editorial claims before publishing.

Player search loads all 32 teams using verified ESPN team IDs, including bye-week teams. The restricted `fantasy-roster` Edge Function retrieves public ESPN rosters server-side because ESPN's directory and some roster responses lack browser CORS headers. It accepts only known NFL team IDs and seasons, never arbitrary upstream URLs, and returns no account data. Deploy it with `supabase functions deploy fantasy-roster` before the UI. Partial roster failures are shown as warnings while available players remain searchable; a completely unavailable roster set shows an explicit retry error.

**Save shared draft** persists work for every admin to edit. Revision checks prevent one admin silently overwriting another's changes. Draft edits do not change the public graphic until **Publish graphic** is selected. The open editor automatically saves player choices, reasoning, searches, the X preference, and the shared revision on this device after each change, independently for each account and week. Returning to that week restores it after navigation, laptop reload, or a phone suspending/restarting the page; this does not depend on browsers showing a leave-page warning. On-device saving failures show a retry warning and retain work in memory across week changes; save a shared draft to protect work if device storage is unavailable. **Close editor** clears the local recovery copy after confirming unsaved changes; replacing a draft also requires confirmation. Clearing browser/app storage removes on-device recovery, so use **Save shared draft** for durable, cross-device access.

Desktop creation uses a compact two-column player grid and a 380px-wide preview so more information fits on screen. Mobile controls and the full-resolution exported artwork are unchanged.

LIVEWIRE push notifications for Start/Sit graphics use compact titles such as **Week 7 Must Start QBs**, with RBs, WRs, or TEs as applicable (and Must Sit for sit graphics). These alerts omit the theme prefix and the word Fantasy; the LIVEWIRE post and X caption keep their full subject.

Weak connections and feed/access refresh failures do not hide or reset the working editor. Temporary missing feed/week data keeps the current editing week, and already loaded players remain available in the open page. The last rendered preview stays visible while updating or after a rendering failure, with a warning when it is not up to date; stale previews cannot be downloaded as the latest graphic. This is screen/draft protection, not a separate offline editor or offline roster library. Shared saving, publishing, and unpublishing require a connection and server-verified admin permissions; reconnecting never publishes automatically.

**Publish graphic** uploads the exact rendered PNG and atomically publishes both the Start/Sit graphic and one linked LIVEWIRE post. Only after a confirmed successful publication, the working template and local recovery copy reset to a blank new graphic, empty searches, and unchecked X preference. The published graphic and saved shared copy remain in their galleries for further editing; failed/interrupted publications keep the working template intact. The LIVEWIRE subject is **Week 7 Must Start Fantasy QB** (using the selected week, Must Start/Must Sit, and QB/RB/WR/TE); the post has only that subject and image, with no body or source link. It appears under Fantasy. Republishing updates that same post, while draft saves do not alter published artwork. Manage linked posts in Start/Sit, not the standalone LIVEWIRE composer. **Unpublish graphic** removes it from both galleries and cancels pending X delivery, while keeping the shared draft; it does not delete a tweet already sent.

**Post to X on first publication** is unchecked by default and is preserved in local recovery. When checked and the existing X connection is enabled, the first LIVEWIRE publication queues a tweet containing exactly its subject and the original graphic PNG, with no extra wording, analysis replacement, or URL. Edits and unpublish/republish do not queue duplicate tweets. Check the delivery status in this area; failures are explicit and ambiguous sends are never automatically retried. No fantasy projections are generated.

The live preview and **2160×2700 PNG** download use the same canvas renderer, actual site fonts, and original ESPN images. Rendering fails visibly on missing fonts/images or copy that exceeds six lines per card rather than clipping the output. Four players, headshots, and reasoning are required to publish/download; incomplete drafts may be saved. Published graphics also include an accessible text analysis view.

### Automatic X publishing

The Angle, Fantasy News, and standalone LIVEWIRE composers have **Post to X on first publication** unchecked by default. Check it explicitly to share a new publication; saved drafts preserve their selected preference. Once the connection is enabled, new checked publications enter a private server queue and are dispatched every minute, one post per invocation to bound image-rendering work. Tweets preserve the headline, distinct subject, every admin pick with the site's sport emoji (plus hit/miss marks when graded), and a link to the source on gamewire.us. Standalone LIVEWIRE has no admin-pick field, so no picks or sport are invented.

The full analysis is rendered server-side as one to four numbered GameWire PNGs (1200px wide, content-sized height up to 1500px) in the site's navy/red theme, with accessible descriptions. Angle/Fantasy analysis includes the narrative and any evidence/counterpoint sections; ordinary LIVEWIRE posts use their body. Original photo uploads are not forwarded except for linked Start/Sit graphics, which send their original PNG and subject only. Rendering uses bundled, licensed Noto fonts and resvg Wasm, without a third-party rendering service or runtime font downloads. The tweet is only created after all PNGs and their accessibility metadata upload successfully through X's v2 media API. If the caption exceeds the conservative 280-character budget, analysis exceeds four readable images, a glyph cannot be rendered, or media permissions/credits fail, delivery shows an explicit failure instead of truncating picks/analysis or sending text-only. Uploaded but unattached media expires on X. Source changes/removal during image preparation prevent the stale tweet.

Generated images also include every admin pick before the analysis, using the same sport emoji and grading marks as the caption. Picks wrap and paginate with the analysis without being dropped. The left accent is a bold 12px saturated red (`#ff182b`) matching the logo's red pulse.

Bundled renderer assets are gzip-compressed to fit the deployment size limit, with their licenses alongside them: [resvg-js 2.6.2 source (MPL-2.0)](https://github.com/thx/resvg-js/tree/v2.6.2), [Noto Sans source (SIL OFL)](https://github.com/notofonts/noto-fonts), and [Noto Emoji source (SIL OFL)](https://github.com/google/fonts/tree/main/ofl/notoemoji). The upstream binaries/fonts are unmodified apart from lossless compression.

The upper-left analysis-image branding uses [`gamewire-site-brand.png`](supabase/functions/send-x-posts/assets/gamewire-site-brand.png), a 4x-resolution rendering of the site's actual header logo and wordmark: [`gamewire-mark.png`](public/gamewire-mark.png), Oswald 600 at 16px with 1px letter spacing, 72×48px mark, and 11px gap. The complete lockup is scaled to 104px high so its lettering matches the original analysis heading's approximately 35px size, with page numbering at the upper right. Its image box starts at x=32px to offset the logo artwork's internal padding and visually align the stadium with the text's 64px left margin. It preserves the header's white wordmark and lighten-blended logo on the analysis background, instead of approximating it with red/white body-font text. Re-export this lockup from the desktop `.brand` markup/styles when the site's branding changes.

Player boards are excluded. Angle mirrors never generate a second tweet; drafts, edits, unpublish/republish, and historical content are not broadcast. An unchecked first publication cannot be broadcast later just by editing it.

Only admins can read connection/delivery status; only the service role can change connection settings, claim deliveries, or record delivery outcomes. The source is checked again before sending. Deleting/unpublishing cancels unsent content but cannot retract tweets already sent, and an in-flight send may still complete.

Apply [`supabase/livewire-views.sql`](supabase/livewire-views.sql) after the LIVEWIRE schema and before deploying the view-count UI. Only signed-in LIVEWIRE owners and admins see the shared view count beneath each post; guests and regular members do not see it. This is a display restriction, not database-level confidentiality: public post responses and the increment RPC still contain totals. Guests, members, and admins count equally; the count increases when any part of a post enters the visible viewport, again after scrolling away/back, reopening LIVEWIRE, or returning to the visible browser tab. Feed polling, editing, and loading older posts do not recount posts that remain visible. Posts below the fold or in hidden tabs do not count. Offline appearances are not uploaded later, but a still-visible post counts on reconnect. Totals start at zero when installed; historical views cannot be reconstructed.

The signed-in LIVEWIRE owner is excluded from all site-open and post-impression counts, including The Angle, Fantasy News, and LIVEWIRE. Apply [`supabase/exclude-owner-views.sql`](supabase/exclude-owner-views.sql) **after** the base site-open and both view-count schemas; it replaces their increment functions, removes the owner's site-open history, and subtracts the one owner impression identified by each old private receipt. Receipts are consumed so rerunning the correction cannot subtract twice. Older owner impressions without receipts cannot be identified retroactively. Other admins, members, and guests retain their existing post-impression behavior. Signed-out visits are guests and cannot be identified as the owner.

The anonymous/authenticated increment RPC performs an atomic increment without granting clients permission to overwrite totals or edit posts. Apart from the private owner/post deduplication receipt, it stores only aggregate counts, not device identifiers, IP addresses, or other viewer accounts. These are impressions, not unique viewers or fraud-resistant analytics: repeat visits and scripted requests can increase them. ## Offline access

After opening the production site online once, GameWire saves its app shell for offline launches, including from a phone's Home Screen. Once the offline worker controls the page, it proactively saves the displayed NFL week's game summaries, both teams' player/season stats, recent-game sources, team logos, and player faces, even for games and team tabs you have not opened. It repeats every five minutes while open, visible, and online, and retries on reconnect or when returning to the app after that interval. Saving runs quietly without an online save-status banner on the website or native apps. Existing live-score polling remains unchanged. Browsing The Wire, Stat Hub, and LIVEWIRE also saves their public responses. Offline browsing is read-only: private account data, favorites sync, sign-in, publishing, and new notifications require internet.

When disconnected, an offline banner warns that scores, game statuses, stats, odds, and projections are snapshots, not live updates. It shows the oldest saved response used on the current page when available and any offline-save errors. Other weeks, searches, filters, matchup-board projections, and older post pages still need to be opened online before going offline. Weekly player faces/logos are explicitly downloaded rather than relying on the browser's temporary image cache. Previously viewed public LIVEWIRE photos are also saved. Upstream missing stats or photos cannot be invented; unavailable requests, storage failures, or incomplete saves are logged. The Locker Room's private account history is not cached by this feature.

The website also writes successful public ESPN/post responses directly into device-local Cache Storage before returning them to the UI, without waiting for service-worker activation. Logos, faces, and public post photos are stored as readable image bytes and rendered from local blob URLs, avoiding a competing initial remote image request. These copies share the worker's bounded public/image stores; cold offline launches can reuse them, and failed refreshes never overwrite the last successful data. A failed scoreboard poll also retains the currently displayed games. On reload, The Wire immediately shows the last saved board for the selected week (including while sign-in restores), and scoreboard requests time out after 10 seconds. With nothing saved, it shows loading placeholders, then a "Retry now" message with automatic 5-second retries, instead of "No NFL games". Weekly warming saves team logos first and player images per matchup rather than waiting for the entire week's stats to finish. A missing image does not stop later image batches, and a failed team save does not skip its opponent; incomplete saves are still recorded as failures. The app requests persistent browser storage when supported, but browser eviction, clearing site data, private browsing, and content never downloaded cannot be covered. Live data is saved on each device, not committed into the source code; reconnecting resumes fresh ESPN reads.

Public API reads display a successful saved response first, without waiting for ESPN, then revalidate quietly online. Concurrent refreshes of the same query/format/filter share one request, with a 15-second minimum between checks to avoid update-triggered loops. Changed response bodies are saved before a batched notification refreshes the affected scoreboard, player/stat panels, news, LIVEWIRE feed, or matchup board. Unchanged responses do not trigger UI updates; existing stats stay visible during refresh and failed refreshes retain the last good copy. Native foreground reads likewise use a disk-only `peek` before background revalidation through the shared native store. Content not previously saved still needs its first download; reading local files and rendering are not literally instantaneous. Only ESPN feeds and the configured project's public LIVEWIRE/matchup-board reads are eligible. Authentication, role checks, private tables, RPCs, writes, and error responses are never cached. Theme/player filters and response formats keep separate cache keys. Public response storage is bounded to 1,500 requests (at most 5 MB each), with 2,500 runtime images to accommodate a full NFL week including defensive players rather than evicting faces after a few teams. Older entries are evicted. Image warming uses four concurrent downloads and game warming two concurrent games. New builds replace the shell cache without touching existing notification routing. Cached public responses may remain after sign-out because they are public. Phones do not guarantee background timers when the app is closed or suspended; no automatic refresh is promised in that state.

Reload/reopen once online after an update to install the new offline worker. Offline access requires a secure origin (HTTPS or localhost), service-worker support, and browser storage; private browsing, storage pressure, or device cleanup can remove saved content. Run `node --test scripts/offline.test.mjs scripts/notification-routing.test.mjs` to check cache rules, isolation, and notification behavior. To verify in a browser, use a production preview (`npm run build`, then `npm run preview`), load public views online, enable network offline mode, and reload. Vite development mode does not cache the development module graph.

For immediate repeat openings, successful loads also retain assembled public scoreboard, player-table, game-box-score, team-average, and roster-detail snapshots in local storage. The Wire and Stat Hub read these synchronously during rendering instead of rebuilding them through the full schedule/roster/history/player-request chain. They are keyed by feed, season, team/game, and selected week; saved totals stay visible if a refresh fails. Full-week warming starts after a five-second opening grace period to reduce startup contention. This additional display store is bounded to 160 entries, roughly 4 MB of UTF-16 text, and 256,000 characters per entry. Rosters are saved once per team/game, not duplicated for both single-team and combined views, and player-table snapshots retain only displayed players. It contains no authentication or private account data and is cleared on account deletion with late writes disabled. Existing installations need one successful load with this version to create assembled display snapshots; never-downloaded data still requires ESPN.

Successful responses replace individual copies; failures retain previous copies. ### NBA push notifications

NBA alerts use the existing per-device **Game updates** (`notify_scores`) preference. An enabled device receives:

### Team matchup-history leads

**Analyst Desk → The Angle → Admin desk** also scans ESPN's calendar-year NFL scoreboards for completed regular-season and playoff meetings between each selected matchup's teams. It uses a rolling five-calendar-year window, inclusive of the starting instant and exclusive of kickoff; the selected game and results dated in the future are excluded. A leap-day start clamps to February 28. The minimum win-rate sample is four meetings, and wins divided by all meetings must be **strictly greater than 70%** (ties count in the denominator, not as wins).

Additional leads flag an unbeaten record in the latest four meetings overall, or the latest four at the upcoming game's home/away configuration, all within the same five-year window. Four unbeaten meetings can include ties and are not labeled four wins. Neutral-site finals count overall but never toward home/away leads; no venue-specific claim is made for an upcoming neutral-site game or when venue classification is unknown. These are franchise/team-ID records, not stadium, coach, roster, ATS, or player-performance trends.

Each private lead includes its W-L-T record, sample size, date window, and individual ESPN game links. **Review this lead** carries the team focus, source, and computed supporting context into an unpublished editor; the admin must still write the headline/storyline and verify the claims before publishing. History is fetched only for admins, in batches of three calendar years, and cached in memory for ten minutes. Failed years suppress affected matchup leads rather than calculate a rate from partial history; malformed final scores and conflicting duplicate games are reported. No qualifying trend is a valid result. Run `node --test scripts/angle-history.test.mjs scripts/the-angle.test.mjs` for threshold, venue, date-window, parsing, and failure regressions.

Locker Room follows the main NFL week selector. Collected score changes, matching headlines, big plays, and player game-stat snapshots are archived by account, season, and NFL week, with no Tuesday deletion of the archive. Signed-in history follows the account across devices; guests keep browser-only history. Player snapshots retain the player's identity even if they are later unfavorited. Save/load failures are visible with a retry action, not a silent browser-only fallback for accounts.

The Following > Players section shows a compact game-stat row: WR/TE receptions/targets, receiving yards and receiving TD; RB rushes, rushing yards and rushing TD; QB completions/attempts, passing yards, passing TD and interceptions. Missing feed values remain unavailable rather than being filled with zero. Loading and refresh failures are shown explicitly. Pregame games do not show a game-stat row.

Favorite a team from its game center or a player from their stats popup. Once signed in, favorites are saved to that user's Supabase account. Your Locker Room combines ESPN headlines matched to favorite names with score/status changes and big-play alerts for favorited NFL players. Scoreboards poll every 30 seconds, latest plays every 15 seconds during relevant live games, and news every five minutes. ESPN public feeds have no availability guarantee.
